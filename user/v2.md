## 1. OAuth2 Login Flow

### Overview

OAuth2 login hoạt động qua **browser redirect** — không dùng AJAX/fetch cho bước authorize.

```
┌─────────┐     1. redirect      ┌──────────┐     2. redirect      ┌──────────┐
│   FE    │ ──────────────────► │ Backend  │ ──────────────────► │ Provider │
│ Client  │                     │ (Spring) │                     │ (Google) │
└─────────┘                     └──────────┘                     └──────────┘
      ▲                              │                                 │
      │    5. JSON response          │    3. callback + code           │
      │                              │ ◄────────────────────────────── │
      └──────────────────────────────┘
         { userId, email, ... }
```

### Step 1: Initiate Login

**Cách đúng:** Redirect browser (không dùng fetch/axios)

```typescript
// ✅ CORRECT - Browser redirect
window.location.href = `http://localhost:3030/api/v1/auth/oauth2/authorize/${provider}`;
// provider = 'google' | 'azure'
```

```typescript
// ❌ WRONG - AJAX call sẽ bị CORS block
const res = await fetch(`/api/v1/auth/oauth2/authorize/${provider}`);
```

### Step 2: Backend xử lý callback

Backend tự động handle callback tại `/login/oauth2/code/{provider}`. FE không cần call endpoint này.

### Step 3: Nhận response

Sau khi login thành công, backend trả JSON:

```json
{
  "code": 200,
  "message": "OAuth2 login successful",
  "data": {
    "userId": 1,
    "email": "user@gmail.com",
    "fullName": "John Doe",
    "avatarUrl": "https://lh3.googleusercontent.com/...",
    "provider": "google",
    "isNewUser": true,
    "isLinked": false,
    "roles": []
  }
}
```

### Response fields

| Field | Type | Ý nghĩa |
|-------|------|---------|
| `userId` | number | ID user trong hệ thống |
| `email` | string | Email từ provider |
| `fullName` | string | Tên đầy đủ |
| `avatarUrl` | string | URL avatar |
| `provider` | string | Provider code: `google`, `azure` |
| `isNewUser` | boolean | `true` = user mới tạo lần đầu |
| `isLinked` | boolean | `true` = link với account có sẵn (qua email) |
| `roles` | string[] | Danh sách role codes (tạm thời empty) |

### FE Integration Pattern

```typescript
// OAuth2LoginButton.tsx
const handleOAuth2Login = (provider: 'google' | 'azure') => {
  // Store current path to redirect back after login
  sessionStorage.setItem('oauth2_redirect_back', window.location.pathname);
  
  // Redirect to backend OAuth2 endpoint
  window.location.href = `${API_BASE_URL}/api/v1/auth/oauth2/authorize/${provider}`;
};

// OAuth2Callback.tsx - Component hiển thị sau khi login
// Backend trả JSON trực tiếp, FE parse và xử lý
useEffect(() => {
  // Backend đã trả JSON, FE cần parse từ response
  // Nếu dùng SPA, cần cấu hình backend redirect về FE với token
  // Hiện tại: JSON response trực tiếp từ backend
}, []);
```

### ⚠️ Lưu ý quan trọng

1. **KHÔNG dùng fetch/axios** cho `/authorize/{provider}` — phải redirect browser
2. **CORS:** OAuth2 flow bypass CORS vì redirect cùng origin
3. **State parameter:** Spring Security tự động generate state để CSRF protection
4. **Session:** Backend dùng STATELESS session — response JSON không tạo session cookie

## 2. User Registration with OTP

### Step 1: Register

```
POST /api/v1/auth/register
Content-Type: application/json
```

**Request:**
```json
{
  "email": "user@example.com",
  "password": "StrongPass123!",
  "fullName": "John Doe"
}
```

**Password requirements:**
- Tối thiểu 8 ký tự
- Ít nhất 1 uppercase
- Ít nhất 1 lowercase
- Ít nhất 1 number
- Ít nhất 1 special character

**Response (200):**
```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "id": 1,
    "email": "user@example.com",
    "fullName": "John Doe",
    "status": "PENDING",
    "emailVerified": false,
    "createdAt": "2026-04-05T10:00:00",
    "notice": "Registration successful. Please verify your email with OTP."
  }
}
```

### Step 2: Verify Email

```
POST /api/v1/auth/verify-email
Content-Type: application/json
```

**Request:**
```json
{
  "email": "user@example.com",
  "otp": "123456"
}
```

**Response (200):**
```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "email": "user@example.com",
    "status": "ACTIVE",
    "emailVerified": true,
    "notice": "Email verified successfully."
  }
}
```

### Step 3: Resend OTP (optional)

```
POST /api/v1/auth/resend-otp
Content-Type: application/json
```

**Request:**
```json
{
  "email": "user@example.com"
}
```

**Rate limits:**
- Cooldown: 60 giây giữa mỗi lần resend
- Maximum: 5 lần resend per OTP window (15 phút)

**Error response (429 - Too Many Requests):**
```json
{
  "timestamp": 1743123456789,
  "code": 6010,
  "error": "Too Many Requests",
  "message": "OTP resend is rate limited for email: user@example.com",
  "path": "/api/v1/auth/resend-otp"
}
```

## 3. Error Handling

### Standard Error Format

```json
{
  "timestamp": 1743123456789,
  "code": 6007,
  "error": "Bad Request",
  "message": "Email already registered and active: user@example.com",
  "path": "/api/v1/auth/register"
}
```

### Auth-related Error Codes

| Code | HTTP Status | Message Template | Khi nào gặp |
|------|-------------|-----------------|-------------|
| 6001 | 404 | User not found with id: %s | User không tồn tại |
| 6002 | 400 | User already exists with username: %s | Username trùng |
| 6003 | 400 | User already exists with email: %s | Email trùng |
| 6007 | 400 | Email already registered and active: %s | Email đã active, không đăng ký lại |
| 6008 | 400 | User email is not pending verification: %s | Email không ở trạng thái PENDING |
| 6009 | 400 | OTP is invalid or expired for email: %s | OTP sai hoặc hết hạn |
| 6010 | 429 | OTP resend is rate limited for email: %s | Resend quá nhanh/quá nhiều |
| 6011 | 500 | Failed to send OTP email to: %s | Lỗi gửi email |

### FE Error Handling Pattern

```typescript
const handleRegister = async (data: RegisterForm) => {
  try {
    const res = await fetch(`${API_BASE_URL}/api/v1/auth/register`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    });
    
    const result = await res.json();
    
    if (!res.ok) {
      // Handle specific error codes
      switch (result.code) {
        case 6007:
          showError('Email này đã được đăng ký và kích hoạt');
          break;
        case 6003:
          showError('Email đã tồn tại trong hệ thống');
          break;
        case 6004:
          showError('Mật khẩu không đủ mạnh');
          break;
        default:
          showError(result.message);
      }
      return;
    }
    
    // Success - navigate to OTP verification
    navigate('/verify-email', { state: { email: data.email } });
    
  } catch (error) {
    showError('Không thể kết nối đến server');
  }
};
```

## 4. OAuth2 Provider List

FE có thể lấy danh sách provider đang active từ:

```
GET /api/v1/providers-config?isActive=true
```

**Response:**
```json
{
  "code": 200,
  "message": "Success",
  "data": [
    {
      "id": 1,
      "provider": "google",
      "displayName": "Google",
      "iconUrl": "https://www.google.com/favicon.ico",
      "sortOrder": 1,
      "isActive": true
    },
    {
      "id": 2,
      "provider": "azure",
      "displayName": "Microsoft",
      "iconUrl": "https://login.microsoftonline.com/favicon.ico",
      "sortOrder": 2,
      "isActive": true
    }
  ]
}
```

### FE Login Page Pattern

```typescript
const LoginPage = () => {
  const [providers, setProviders] = useState<Provider[]>([]);

  useEffect(() => {
    // Fetch active providers
    fetch(`${API_BASE_URL}/api/v1/providers-config?isActive=true`)
      .then(res => res.json())
      .then(result => setProviders(result.data));
  }, []);

  const handleProviderLogin = (providerCode: string) => {
    window.location.href = `${API_BASE_URL}/api/v1/auth/oauth2/authorize/${providerCode}`;
  };

  return (
    <div>
      {providers.map(p => (
        <button key={p.provider} onClick={() => handleProviderLogin(p.provider)}>
          <img src={p.iconUrl} alt={p.displayName} />
          Login with {p.displayName}
        </button>
      ))}
    </div>
  );
};
```

## 8. Common Mistakes to Avoid

| Mistake | Correct Approach |
|---------|-----------------|
| Dùng `fetch()` cho `/authorize/{provider}` | Dùng `window.location.href` redirect |
| Gọi `/login/oauth2/code/{provider}` trực tiếp | Spring Security tự handle |
| Expect JWT token trong response | Hiện tại trả JSON user info, chưa có JWT |
| Lưu session cookie | Backend STATELESS — không có session |
| Hardcode provider list | Fetch từ `/api/v1/providers-config` |
